# Подпись Android APK

Основной Android 1.0.28 подписан прежним ключом Windows и совместим
по подписи с опубликованной 1.0.16. Ранний тестовый APK с ключом Mac
сохранён в том же релизе; у него другой сертификат:

| APK | SHA-256 сертификата |
| --- | --- |
| Опубликованный 1.0.16 и основной 1.0.28 | `05646e3ba6891a351bd5b4afe58d66a590ad673819fb4a24e580ed81c67f6dad` |
| Тестовый 1.0.28 с Mac | `e1f2ea2102a135d60e85cf9d80f6cbdc18ad817d3027c96f1140d9f0e5ee9be8` |

Отпечатки проверены по APK, а не по имени файла. У обоих сертификатов
имя Android Debug. Тип сборки 1.0.28 — release;
тестовая подпись не означает запуск через сервер разработки.

## Что означает другой ключ

При обычной установке обновления Android проверяет подпись. Новый ключ
не позволяет обновить приложение поверх прежнего с тем же package
`com.lomify.next`. Отклонённое обновление не удаляет старое приложение.
Первая установка на другом устройстве работает; дальнейшие обновления
такой установки требуют того же нового ключа и большего versionCode.
Удаление приложения перед переустановкой уничтожает его локальные данные.
Нельзя менять package или удалять приложение только ради обхода проверки
без отдельного согласования с владельцем.

Ротация ключа с сохранением совместимости — отдельная процедура, которой
также нужен прежний закрытый ключ. Из APK или `.apk.idsig` его восстановить
нельзя. Официальные сведения: [подпись Android](https://developer.android.com/studio/publish/app-signing),
[проверка обновлений](https://developer.android.com/google/play/app-updates),
[apksigner](https://developer.android.com/tools/apksigner).

## Где искать прежний ключ на Windows

Обычный debug-keystore создаётся вне проекта. На ПК открой через
Win + R папку `%USERPROFILE%\.android` и найди `debug.keystore`.
В Android Studio путь можно проверить через Gradle → app → Tasks →
android → signingReport, поле Store. Если путь отличается, нужен файл
из этого поля.

Скопируй keystore в личную папку на диске, доступном Mac, и передай
его локальный путь. Не отправляй пароль в чат и не добавляй файл в Git.
Перед использованием сначала сравнивается публичный отпечаток
сертификата с 1.0.16. Совпавшее имя или наличие APK рядом с проектом
не подтверждает, что это нужный ключ.

Прежний ключ проверен после копирования владельцем с Windows. На Mac
его отдельная копия находится в `~/.android/lomifynext-original.keystore`,
вне проекта, с правами 0600. Обычные будущие APK следует подписывать им.
Стандартный `~/.android/debug.keystore` не заменялся: им подписана только
ранняя тестовая 1.0.28. Не удаляй эти ключи, если планируются совместимые
обновления соответствующих установок. Keystore, JKS, P12 и PFX исключены
в `.gitignore`; APK публикуется как бинарный asset релиза.

## Публикация 1.0.28

`android-v1.0.28` — отдельный pre-release. Для обновления старой
GitHub-версии скачивай **`LomifyNEXT-1.0.28-arm64.apk`**. Сравнение
сертификата и versionCode выполнено непосредственно по APK 1.0.16 и 1.0.28;
содержимое 960 записей приложения после подписи не изменилось.
Checksum основного APK находится в `SHA256SUMS-original-key.txt`.

`LomifyNEXT-1.0.28-arm64-test.apk` оставлен для прежних тестовых установок
с сертификатом Mac. Суффикс `-test` исключает его из шаблона автоматических
обновлений, включая проверку в 1.0.16. Только флага pre-release недостаточно:
проверка рассматривает и такие релизы. Основной APK по обычному шаблону
выбирается проверкой обновлений. Исходники Android находятся в `main`;
`ios` остаётся веткой iPhone.
