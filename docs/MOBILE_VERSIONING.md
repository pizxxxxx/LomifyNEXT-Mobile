# Версии мобильных сборок

Каждая новая сборка, которую передаём пользователю после изменений, получает
новую видимую версию. Пример: 1.0.17 → 1.0.18 → 1.0.19. Одного увеличения
внутреннего номера недостаточно: версию должно быть легко отличить в настройках
и в названии файла IPA/APK.

Одна итерация для iOS и Android имеет общую версию. Повторная компиляция при
устранении ошибки сборки, проверка симулятора и сборка второй платформы в рамках
этой итерации не требуют ещё одного увеличения.

Перед следующей выдачей сборки:

```sh
npm run version:next
```

Скрипт увеличивает patch-версию в npm, Cargo, Tauri, интерфейсе и существующих
сгенерированных мобильных проектах, а также увеличивает Android versionCode
и iOS bundleVersion. Можно явно указать более высокую версию:
`npm run version:next -- 1.1.0`. Скрипт сначала проверяет все файлы и отказывается
применять прежнюю или более низкую версию. Ничего не устанавливает и не публикует.

Перед сборкой проверять согласованность:

```sh
node scripts/mobile-version.mjs --check
```

Добавлять заметку в `src/lib/changelog.ts` и `docs/releases/v<версия>.md`.
Хранить выданные файлы под именами с версией, сохранять прежние архивы.
Проверять версию внутри готового IPA/APK. Сборка Android для обновления требует
того же ключа подписи, что и установленное приложение.
