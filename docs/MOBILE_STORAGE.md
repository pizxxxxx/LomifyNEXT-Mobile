# Сохранение большой медиатеки на iOS и Android

После импорта Яндекса необработанная ошибка `localStorage.setItem` могла выйти
из подписчика `likedTracks` или `playlists`. В установленной версии Svelte такая
ошибка прерывает обработку общей очереди подписчиков: новые значения вкладок
уже не доходят до интерфейса. CSS-прокрутка при этом продолжает работать.
Это воспроизведено на реальном `stores.ts` с искусственной ошибкой квоты.

`storePersistence.ts` сохраняет небольшие значения в прежних ключах localStorage,
а большие списки и значения, не поместившиеся туда, — в IndexedDB
`LomifyNextState`. JSON больше 128 Ки символов сразу направляется в IndexedDB.
Старые значения localStorage сохраняются как резервные копии. Если для ключа
есть запись IndexedDB, при запуске используется она, включая пустой список
после сознательной очистки медиатеки. Миграция не обрезает треки и метаданные.

Записи объединяются и выполняются последовательно; импорт дожидается завершения
сохранения. Фоновая сверка при запуске дожидается восстановления данных.
Настройки, изменённые во время запуска, объединяются с восстановленными:
автоматические мобильные параметры не сбрасывают подключённый аккаунт.
Ошибка обеих систем хранения показывает уведомление, сохраняет текущую
медиатеку в памяти и оставляет переключение вкладок рабочим. Следующее
сохранение повторяет попытку; недоступность диска всё равно не позволяет
гарантировать сохранение после закрытия приложения.

Это общий код iOS, Android и десктопа. Оформление UIKit остаётся отдельным
кодом iOS; Android использует прежние кнопки Svelte.

Проверки:

- `node scripts/mobile-storage-test.mjs`: импорт 1800 треков и 30 плейлистов,
  переключение вкладок, полные метаданные, сохранение старых копий, восстановление
  после запуска, настройка аккаунта, недоступность обоих хранилищ и повтор записи.
- `node scripts/playlist-sync-test.mjs`: 22 проверки синхронизации плейлистов.
- Проверка на WebKit в отдельной локальной тестовой странице: настоящая запись
  IndexedDB, импорт тех же больших списков, переключение вкладок, принудительная
  ошибка localStorage и восстановление после перезагрузки.
- Сборки device IPA, симулятора iOS и тестового ARM64 Android APK проходят.

Тесты используют вымышленные данные и не читают пользовательские токены.
Импорт конкретного аккаунта на физическом iPhone после обновления ожидает
проверки владельцем устройства.

Сведения о квотах и ошибках хранения:
[WebKit — Updates to Storage Policy](https://webkit.org/blog/14403/updates-to-storage-policy/).
