# SoundCloud Desktop и scnative: что полезно для Lomify

Проверено 4 октября 2026 года по [оригинальному репозиторию](https://github.com/zxcloli666/SoundCloud-Desktop),
`main`, commit `50a71b2da5549510f2e7b6faa5acd4875010849e`. Это обзор исходников клиента;
доступность авторизованного поиска и стриминга на физическом телефоне не проверена.

## Что такое scnative

`scnative.space` — семейство серверов SoundCloud Desktop: API, поиск, изображения,
стриминг, хранилище и резервные relay-узлы. Это не npm-пакет и не самостоятельный
локальный декодер. Подключить отдельные HTTP-функции к Svelte/Tauri можно; копирование
фронтенда не создаёт сервер, индекс или права доступа к ним.

В Lomify уже подключён `api.scnative.space` для экспериментального поиска по словам
и свободному описанию настроения. Обычный каталог SoundCloud и Яндекс работают
независимо. Отдельная сессия scnative используется только с этим сервером; токен
Яндекса ему не отправляется. Название SoundCloud Desktop в браузере относится к
их зарегистрированному OAuth-клиенту. Переименование кнопки Lomify не меняет
название внешнего приложения на странице авторизации.

Поиск по словам ищет в текстах, сохранённых в их индексе, а не гарантированно во
всём каталоге SoundCloud. Клиент описывает режимы `text`, `semantic` и `auto`;
Lomify использует `text` и показывает `matchedLine` на обложке. Поиск настроения
использует серверное сопоставление описания со звучанием. Ответ `preparing`
означает, что сервер ещё готовит результат; модели на телефон не устанавливаются.
[Контракты поиска](https://github.com/zxcloli666/SoundCloud-Desktop/blob/50a71b2da5549510f2e7b6faa5acd4875010849e/desktop/src/lib/hooks.ts).

## Что стоит адаптировать

| Механизм | Польза для Lomify | Зависимость |
| --- | --- | --- |
| Выбор direct/relay по результатам соединения с периодической перепроверкой | Не ждать заново неработающий маршрут при каждом треке | Алгоритм можно реализовать отдельно; relay-адреса требуют реально работающих серверов |
| Второй маршрут через 300 мс, соревнование только до ответа заголовков | Медленный первый сервер не задерживает начало загрузки; проигравший запрос отменяется до чтения аудио | Нужны два разрешённых маршрута; переносить весь файл дважды не требуется |
| Один срок ожидания на всю цепочку с резервом для запасного адреса | Несколько попыток не умножают задержку; отмена выбора трека сразу прерывает цепочку | Можно внедрить в текущий Rust/TypeScript транспорт без scnative |
| Разделение сетевого отказа, 401, 429 и отсутствующего трека | Не предлагать повторный вход из-за недоступного маршрута; не повторять бесполезно отказ доступа | Независимо от серверов; изменения аккаунта нельзя бездумно повторять на нескольких узлах |
| Обложка: кэш, ограниченный переход на запасной адрес, затем исходный URL | Меньше пустых обложек и повторных загрузок | Локальный кэш в Lomify уже есть; их удалённый images-сервис — отдельная зависимость |
| Метаданные по требованию, подготовка следующего трека | Не запускать тяжёлую загрузку для каждой карточки во время прокрутки | Частично уже реализовано в Lomify: lazy resolution найденного трека и prefetch |

## Что означают средства обхода

В просмотренном сетевом слое прямой адрес сервиса заменяется на relay-узел той же
инфраструктуры. Это полезно при сетевой блокировке или отказе маршрута; это не
универсальный VPN для любого домена. Его алгоритм можно адаптировать, но чужой
relay-пул не становится собственным сервером Lomify.

`stream.scnative.space`, `/download/:urn`, `/stream/:urn` и удалённое `.m4a`-хранилище
могут выступать резервами их клиента. Часть запасных `star`-адресов доступна только
при премиуме проекта и возвращает 403 обычному пользователю. Некоторые функции
разрешения защищённых потоков выполняются на сервере. Из исходников клиента нельзя
заключить, что Lomify получит такие же возможности или что это будет доступно без
их сессии и условий доступа. [Разрешение потоков и ограничения запасных адресов](https://github.com/zxcloli666/SoundCloud-Desktop/blob/50a71b2da5549510f2e7b6faa5acd4875010849e/desktop/src/lib/streaming.ts).

Сейчас разумно оставить основной звук SoundCloud через доступные прямые потоки,
а scnative использовать как дополнительный поиск. Следующий полезный шаг для
движка — ограниченные повторы, общий срок ожидания и выбор рабочего маршрута.
Добавление их стриминга требует отдельной проверки обычного аккаунта, отсутствия
доступа и отмены загрузки на обеих мобильных платформах.

## Что исправлено в 1.0.33

Сопоставление с `useLyricSearch` выявило ошибку протокола: пагинированный ответ
содержит `collection` и `has_more`, а Lomify читал `items`. Исправлено чтение
результатов и следующей страницы; для настроения сохранён его отдельный формат
`items`. Регрессионный тест воспроизводит фактический конверт ответа. Настоящая
выдача после входа пользователя пока не подтверждена.

Сетевой движок и чужие relay-узлы в этой версии не добавлялись. Обзор отделён от
проверенных исправлений. Проект имеет [лицензию MIT](https://github.com/zxcloli666/SoundCloud-Desktop/blob/50a71b2da5549510f2e7b6faa5acd4875010849e/LICENSE):
при переносе существенных частей кода нужно сохранить уведомление о лицензии.
