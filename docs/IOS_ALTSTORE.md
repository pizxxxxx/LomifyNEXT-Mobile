# LomifyNEXT Mobile на iPhone через AltStore Classic

Версия приложения: 1.0.22. iOS bundle identifier:
`io.github.pizxxxxx.lomifynext.mobile` (отдельный `tauri.ios.conf.json`).
Android сохраняет свой идентификатор из основной конфигурации.

**Статус подготовки:** Apple-проект создан, приложение запускается на ARM64
симуляторе iPhone 17 с iOS 27. Нативная навигация UIKit, переключение четырёх
вкладок и скрытие панели в большом плеере проверены пользователем. Встроенный
аудиомост FFmpeg проверен на реальных аудиофайлах. Device IPA без подписи собрана
с нативными круглыми кнопками Liquid Glass и свайпом вниз для закрытия плеера.
Эти новые взаимодействия ожидают ручной проверки. Пользователь запускал LomifyNEXT
на iPhone и сообщил о зависании после импорта Яндекса. Проверка исправления и звука
версии 1.0.22 на устройстве ещё не подтверждена; AltStore уже установлен.
Свайп назад и обновлённые общие экраны проверены в WebKit. Проверку кнопок
артиста под удерживаемым пальцем на iPhone пользователь отложил.

Готовый локальный архив: `src-tauri/target/ios-dist/LomifyNEXT-1.0.23.ipa`.
Скачивание с GitHub: [iOS 1.0.23](https://github.com/pizxxxxx/LomifyNEXT-Mobile/releases/tag/ios-v1.0.23).
Отдельные iOS-релизы используют тег `ios-v<версия>` и содержат IPA. Android APK
в них не публикуются; Latest остаётся за Android-релизом.
Он содержит ARM64-приложение для устройства с минимальной iOS 15.0, без
персонального provisioning profile, внешних `ffmpeg`/`ffprobe` и файлов `.env`.
Нативные стеклянные кнопки доступны на iOS 26+; на старых версиях остаются
существующие кнопки интерфейса.

Сборка 1.0.22 (10015) от 1 октября 2026 года включает новый спокойный экран
станции: тонкие SVG-линии на тёмном фоне, запуск в центре, компактное
«Настроить» и текущий трек отдельной строкой. Фильтры и управление сохранены.
Овалы заметнее расширяются на басе и слегка поворачиваются при ударе;
на паузе, в тишине и при отключённых анимациях движение прекращается.
В 1.0.22 исправлена остановка отклика на плотной музыке после первых ударов:
детектор учитывает изменения отдельных частот, а мобильный спектр больше
не обрезает громкие амплитуды до одинакового максимума.
Все исправления 1.0.17–1.0.19, свайп назад и UIKit-кнопки также сохранены.
Размер 21 694 385 байт,
SHA-256 `d4d7b1d40a7f16f0442ec823dda2ce187674f8371b18d4caf6035ed2efdcdb2f`.
При новой сборке контрольная сумма изменится.

Подробности исправления импорта и проверки обеих мобильных платформ:
[MOBILE_STORAGE.md](MOBILE_STORAGE.md). Для обновления выбирайте новый IPA через
AltStore, сохраняя существующую установку и её данные.
UI-проверка и её границы: [MOBILE_UI.md](MOBILE_UI.md).
Дизайн и проверка станции: [MOBILE_WAVE.md](MOBILE_WAVE.md).

## 1. Подготовить Mac и собрать приложение

1. Установите полную версию Xcode, откройте её и завершите установку компонентов.
   В Settings → Components установите runtime iOS Simulator. Проверьте
   `xcodebuild -checkFirstLaunchStatus` и `xcrun simctl list devices available`.
   Если требуется `sudo xcodebuild -runFirstLaunch`, выполняйте её в своём Terminal.
2. В корне проекта установите локальные npm-зависимости: `npm ci`.
3. Если отсутствуют, установите Rust-таргеты:
   `rustup target add aarch64-apple-ios aarch64-apple-ios-sim`.
4. Проверьте `pod`, `xcodegen` и `idevice_id`. При отсутствии нужных инструментов
   установите их через Homebrew: `brew install cocoapods xcodegen libimobiledevice`.
   Tauri `ios init` может автоматически вызвать Homebrew для недостающих
   `xcodegen` и `libimobiledevice`, поэтому проверяйте их до инициализации.
   Для release-сборок Swift под Xcode 27 также нужен
   `rustup component add llvm-tools`: Tauri использует `llvm-objcopy` для экспорта
   функций плагинов. Если компонент установили после неудачной сборки, повторите
   сборку Swift-библиотек согласно [IOS_XCODE27.md](IOS_XCODE27.md).
5. Соберите встроенные библиотеки аудио:

   ```sh
   bash scripts/build-ios-ffmpeg.sh aarch64-apple-ios
   bash scripts/build-ios-ffmpeg.sh aarch64-apple-ios-sim
   ```

6. Инициализируйте проект:

   ```sh
   node scripts/ios-tauri.mjs init --skip-targets-install
   ```

   Должен появиться `src-tauri/gen/apple`. Скрипт использует локальный Tauri CLI
   и направляет Vite/SvelteKit в отдельный пустой каталог переменных окружения;
   `.env` репозитория в этих командах не загружается. Значения Last.fm для своей
   сборки можно передать самостоятельно через переменные процесса. Обычная
   команда `npm run tauri -- ios build` использует стандартную конфигурацию проекта.
   После `init` скрипт также настраивает фазу Rust в Xcode на локальную команду
   `scripts/ios-xcode-build.sh`, подключает системный zlib и MediaPlayer, копирует
   существующие иконки Lomify из `src-tauri/icons/ios` вместо иконки Tauri.
   Для уже созданного проекта: `node scripts/ios-tauri.mjs prepare-project`.

7. Для первого запуска на симуляторе:

   ```sh
   node scripts/ios-tauri.mjs dev
   ```

   Выберите доступный iPhone Simulator. Для проверки компиляции без запуска:
   `cargo check --manifest-path src-tauri/Cargo.toml --target aarch64-apple-ios-sim --lib`.

8. Для установки на настоящий iPhone соберите **device ARM64**, не simulator:

   ```sh
   node scripts/ios-tauri.mjs build --target aarch64 --no-sign
   ```

   Флаги `--no-sign` и `--archive-only` подтверждены в локальном CLI 2.11.2.
   Для AltStore нужен законченный IPA; не добавляйте `--archive-only` в обычную
   сборку. Путь к результату напечатает CLI. Для поиска:
   `rg --files --no-ignore src-tauri/gen/apple -g '*.ipa'`.

Мы выбираем IPA без персонального сертификата и профиля. AltStore/AltServer
подпишет приложение Apple ID владельца iPhone. Сборке не требуется платная
команда разработчика или профиль конкретного устройства. На телефоне приложение
будет подписано — установка самого неподписанного архива напрямую не работает.
Для бесплатной подписи через Xcode можно выбрать Personal Team, но это отдельный
путь; для распространения IPA через AltStore заранее такая подпись не нужна.

Описание аудиосборки и её проверки: [IOS_FFMPEG.md](IOS_FFMPEG.md).
Нативные кнопки и навигация: [IOS_UIKIT.md](IOS_UIKIT.md).
Исправления для установленного SDK: [IOS_XCODE27.md](IOS_XCODE27.md).

## 2. Установить AltServer и AltStore Classic

1. Скачайте AltServer для macOS с [официального сайта](https://altstore.io/).
   Переместите `AltServer.app` в `/Applications` и запустите. На проверенном Mac
   уже имеется AltServer 1.7.2; перед использованием проверьте обновления через
   его меню.
2. Подключите iPhone кабелем, разблокируйте его и подтвердите доверие компьютеру.
3. Откройте iPhone в Finder → General. Включите **Show this iPhone when on Wi-Fi**
   («Показывать этот iPhone при подключении к Wi-Fi») и примените настройку.
4. В меню AltServer выберите **Install AltStore → ваш iPhone**. Используйте
   бесплатный Apple ID. Вводите данные учётной записи только в интерфейсе AltServer;
   сертификаты и пароли не нужны в репозитории.
5. Дождитесь уведомления об установке. На iPhone откройте Settings → General →
   VPN & Device Management, выберите свой профиль и подтвердите доверие.
6. На iOS 16+ включите Settings → Privacy & Security → Developer Mode и выполните
   предлагаемый перезапуск/подтверждение. Если AltServer отдельно просит Mail
   Plug-in, следуйте соответствующей инструкции для установленной версии macOS;
   не устанавливайте старые плагины без такого запроса.

Официальная [инструкция установки на macOS](https://faq.altstore.io/altstore-classic/how-to-install-altstore-macos).

## 3. Установить LomifyNEXT IPA

1. Убедитесь, что AltServer запущен, Mac не спит, а iPhone доступен по кабелю либо
   находится с Mac в одной Wi-Fi-сети. Для первой установки предпочтителен кабель.
2. Передайте готовый **device IPA** на iPhone, например через AirDrop, и сохраните
   его в приложении Files («Файлы»).
3. Откройте AltStore Classic → **My Apps → +** и выберите IPA в Files.
4. Если AltStore запросит вход, используйте тот же Apple ID. Дождитесь завершения
   подписи и установки; затем откройте LomifyNEXT.
5. Проверьте главную страницу, настройки, вход в используемые музыкальные сервисы,
   воспроизведение MP3/AAC/Opus, перемотку, экспорт с обложкой и офлайн-загрузки.
   Отдельно проверьте наушники, блокировку экрана и восстановление после звонка.

Ошибку **Could not find AltServer** сначала проверяйте подключением кабеля,
запуском AltServer и повторным подтверждением доверия в Finder. В Wi-Fi-сети
должно быть разрешено обнаружение устройств; гостевые сети часто его блокируют.
Подробнее: [официальное устранение неполадок](https://faq.altstore.io/altstore-classic/troubleshooting-guide).

## 4. Обновить версию приложения

1. Получите новый IPA, собранный для устройства с тем же bundle identifier.
2. Используйте тот же Apple ID и снова установите IPA через **My Apps → +**.
   Не удаляйте старую установку перед обновлением: её данные и офлайн-файлы
   находятся в контейнере приложения.
3. Проверьте номер версии в приложении и срок подписи в AltStore.

Изменение bundle identifier или Apple ID может превратить обновление в отдельную
установку. Для последовательных релизов сохраняйте идентификатор и увеличивайте
версию приложения/номер сборки. Кнопка **Refresh All** продлевает подпись уже
установленной версии; она сама по себе не скачивает новую ручную IPA-сборку.

## 5. Продлить подпись и восстановить истёкшую установку

При бесплатном Apple ID приложения действуют **7 дней** после подписи. Пока
AltServer доступен, откройте AltStore → My Apps → **Refresh All**. Успешное
обновление подписи начинает новый семидневный срок для каждого обновлённого
приложения, включая AltStore. Проверяйте срок заранее, например раз в несколько
дней; фоновое продление зависит от доступности Mac и не гарантировано.

Для фонового продления включите Background Refresh в AltStore и разрешите
Background App Refresh для AltStore в настройках iPhone. AltServer должен быть
запущен, Mac бодрствовать, устройства — видеть друг друга в Wi-Fi.

Если срок истёк:

1. Если AltStore открывается, подключите iPhone к Mac с запущенным AltServer и
   нажмите Refresh All.
2. Если AltStore тоже истёк и не открывается, заново установите **AltStore** из
   меню AltServer на тот же iPhone с тем же Apple ID, затем откройте AltStore
   и продлите LomifyNEXT. Перед этим не удаляйте приложения вручную.
3. Если продление LomifyNEXT не восстановилось, повторно установите сохранённый
   IPA с тем же идентификатором и Apple ID. Сначала разберитесь с ошибкой подписи,
   чтобы не потерять данные из-за удаления приложения.

Истечение подписи блокирует запуск; оно не заменяет обновление приложения новой
версией. Официальное описание: [My Apps и Background Refresh](https://faq.altstore.io/altstore-classic/your-altstore).

## 6. Ограничения бесплатного Apple ID

- На устройстве можно иметь **3 активных sideload-приложения**, включая сам
  AltStore: обычно остаются два слота для LomifyNEXT и ещё одного приложения.
- Можно иметь **до 10 зарегистрированных App ID одновременно**; они действуют
  неделю. Каждое расширение приложения также может расходовать отдельный App ID.
  Истекающие идентификаторы и даты видны в **My Apps → View App IDs**.
- Удаление приложения не освобождает зарегистрированный App ID немедленно:
  при достижении лимита требуется дождаться истечения идентификаторов.
- Не меняйте bundle identifier между каждой сборкой. В текущем проекте нет
  специально добавленных iOS-расширений приложения.
- Ограничения и подпись не требуют оплаты Apple Developer Program для этого пути.

Источники: [активные приложения](https://faq.altstore.io/altstore-classic/your-altstore),
[App IDs](https://faq.altstore.io/altstore-classic/app-ids).

## 7. Предложенная схема обновлений — ещё не создана

После отдельного подтверждения можно публиковать IPA в GitHub Releases, а JSON
source AltStore — на GitHub Pages этого репозитория. Source будет содержать
стабильный bundle identifier, версию, дату релиза, описание изменений, размер
и ссылку на IPA соответствующего релиза. Пользователь добавляет URL source в
AltStore и получает обновления через его интерфейс. Подписание/продление всё
равно выполняется через AltServer своим Apple ID.

Source-файл и GitHub Pages пока не созданы. Публикация IPA в отдельных
GitHub Releases разрешена пользователем; автоматический source остаётся
предложением и требует отдельного подтверждения. Формат: [Make a Source](https://faq.altstore.io/distribute-your-apps/make-a-source).

Новая выдаваемая сборка всегда получает более высокую видимую версию.
Правило и команда: [MOBILE_VERSIONING.md](MOBILE_VERSIONING.md).
