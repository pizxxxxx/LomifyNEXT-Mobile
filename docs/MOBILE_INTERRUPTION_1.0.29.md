# Возврат к музыке после прерывания в 1.0.29

Сообщённый случай: на Android после сброса звонка музыка не возвращалась.
Случай передан со слов владельца другого телефона, без записи и логов.

## Обнаруженные причины

Android обрабатывал потерю аудиофокуса как обычную паузу, после которой
сервис вызывал abandonAudioFocusRequest. Он также не обрабатывал GAIN.
Сохранить запрос во время временного прерывания и обработать возврат
соответствует [рекомендациям Android](https://developer.android.com/media/optimize/audio-focus).
Foreground notification теперь создаётся до запроса фокуса, как требуется
для фоновой работы при target SDK 35+. Отложенный запрос не начинает
проигрывание до получения фокуса; отказ оставляет музыку на паузе.

iOS ставил блокировку ещё в нативном callback, затем считывал
engine::is_playing в worker: блокировка уже делала ответ false.
Теперь состояние захватывается до блокировки из последнего нативного
состояния воспроизведения. Возврат учитывает [рекомендацию AVAudioSession](https://developer.apple.com/documentation/avfaudio/avaudiosession/interruptionnotification)
и результат активации аудиосессии.

## Правила

| Событие | Поведение |
| --- | --- |
| Звонок прерывает играющую музыку | Запоминается намерение продолжить; плеер ставится на паузу |
| Временное прерывание закончено и система разрешает звук | Музыка продолжается один раз |
| До звонка музыка была на паузе | Музыка сама не запускается |
| Пользователь нажал паузу/стоп во время звонка | Автоматическое продолжение отменяется |
| Во время звонка отключены наушники | Пауза сохраняется после возврата звука |
| Другое приложение забрало фокус надолго | Автоматического продолжения нет |
| Повторные уведомления потери/возврата | Первоначальное намерение не затирается; второй возврат не запускает звук повторно |
| Длительный звонок | Android не завершает сервис по таймеру обычной паузы во время прерывания; wake lock при паузе освобождён |

Прерывание фиксируется до очереди команд, чтобы завершившееся
декодирование или восстановление выхода не включило музыку во время звонка.
Ручные команды и возврат прерывания обновляют флаги под одним mutex;
частая проверка паузы использует atomic. WebView не нужен для возврата звука.
Во время отложенного кроссфейда играющий исходящий трек также считается
воспроизведением на Android, как уже было на iOS.

## Проверки и границы

Rust-тесты обоих платформенных playback gate проверяют повторное
прерывание, разрешение системы, предыдущую паузу, отмену ручной паузой
и отключением выхода, а также паузу во время декодирования.
Kotlin/JUnit проверяет сохранение запроса при звонке, отложенное получение
и освобождение при ручной паузе или постоянной потере.
Проверяется текущий код выбора общего релиза и старый Android-код 1.0.16.

Пройдены 4 Rust-теста Android, 5 Rust-тестов iOS и 3 Kotlin/JUnit-теста.
Svelte/TypeScript: 0 ошибок и 0 предупреждений; проверки мобильных функций,
фонового воспроизведения, переходов, обновлений и версии прошли.
Собраны production APK ARM64 и device IPA ARM64. В каждом нативном архиве
проверено соответствие всех 23 JS/CSS-файлов его сборке интерфейса.
APK проверен по исходному сертификату, выравниванию страниц 16 КБ и версии;
IPA — по платформе iPhoneOS, версии, отсутствию персонального профиля
и файлов `.env`.

Реальный входящий звонок на устройстве, Bluetooth, длительный звонок,
переход Android foreground service в фоне и состояние телефонной
медиатеки после обновления не проверены. Логи сборки и отчёты тестов
остаются локально в `src-tauri/target`.
