# Android 1.0.28: общий интерфейс с iOS 1.0.27

Android-ветка начинается с iOS 1.0.27, чтобы сохранить все накопленные
изменения общих Svelte-компонентов. Платформенные части защищены `cfg`:
UIKit, SF Symbols, AVAudioSession и Xcode не попадают в Android-бинарник.
Android сохраняет собственные MediaSession, foreground service,
системную громкость и кнопку «Назад». На iPhone остаётся UIKit;
на Android кнопки находятся в одном DOM-слое со страницей и плеером.
Настоящий системный Liquid Glass на Android не используется.

| Функция | Android 1.0.28 |
| --- | --- |
| Компактные настройки и параметры шрифта/темы | Общие с iOS |
| Импорт большой медиатеки без синхронной записи всего хранилища | Общие очереди сохранения и исправления импорта |
| Жест от левого края назад и свайп плеера вниз | Общие действия; системная кнопка Android также сохранена |
| Обложка карточки переходит в шапку плейлиста | Общая анимация, включая «Любимые треки» |
| Обложка размывается и освобождает видео под текстом | Общий компонент плеера и настройки видео |
| Эдлибы не исчезают с новой основной строкой | Общая шкала времени, яркость и отдельный сдвиг |
| Обложки релизов артиста | Общие пресеты CDN и ограниченная повторная попытка |
| Информация о треке | Жанр, релиз и доступные счётчики источника; неизвестные значения не выдумываются |
| «Моя волна» по нажатию начинает играть | Общая обработка запуска, фильтры и реакция колец на музыку |
| Пауза и неподвижный интерфейс | Общие ограничения FFT, событий прогресса и фоновой активности |
| Проверка обновления | Существующая проверка APK; IPA и черновики пропускаются |
| Следующий/предыдущий при погашенном экране | Добавлена обработка подготовленной очереди непосредственно в Rust |
| Пауза при отключении выхода | Android-пауза фиксируется до завершения декодирования; восстановление UI читает состояние движка |

Очередь заранее разрешает текущий, предыдущий и до двух следующих источников.
Если подготовленного источника нет, команда возвращается интерфейсу;
бесконечная очередь рекомендаций без активного WebView не обещается.
Декодер Android MP3/AAC сохранён: встроенная iOS-библиотека FFmpeg
не переносилась в Android. Никакая существующая Android-функция не удалялась.

Системное отключение выхода принимается в Activity ещё во время загрузки
первого трека, когда PlaybackService может не существовать. Обработчик
только фиксирует паузу и передаёт команду рабочему потоку. Регистрация
системного receiver следует [документации Android](https://developer.android.com/develop/background-work/background-tasks/broadcasts).

## Проверки

Использованы прежние принципы `better-ui`: та же плотность, размеры значков,
цвета темы и движение обложки, без новых декоративных поверхностей.

| Severity | Location | Before | After | Why |
| --- | --- | --- | --- | --- |
| HIGH | `src-tauri/src/android_media.rs:56`, `src/lib/components/Player.svelte:400` | Системные next/previous требовали доставки события спящему WebView; предыдущий источник готовился только на iOS | Android управляет подготовленной нативной очередью, интерфейс согласует её историю после возвращения | Видимое состояние и работоспособность системного управления |
| HIGH | `src-tauri/src/audio/engine.rs:344`, `src-tauri/src/android_playback_gate.rs:4` | Окончание загрузки могло снова запустить музыку после системной паузы | Отдельная Android-защёлка проверяется перед публикацией декодера и запуском; UI не повторяет play при восстановлении | Прерывание не теряет состояние пользователя |

Passed: Svelte/TypeScript без ошибок и предупреждений; проверки фоновой
истории выполняются отдельно для iOS и Android; Android-тест паузы во
время декодирования; общие тесты движения, жестов, idle, эдлибов, волны,
видео, информации о треке и выбора обновлений. ARM64 release APK собран.
Нативные Kotlin/JNI-команды компилируются; общий Rust также проверен
для `aarch64-apple-ios` без сборки или публикации новой IPA.

В локальном WebKit на тестовых данных включён именно Android-вариант
компонентов: UIKit-кнопок нет, плеер открывается и закрывается,
обложка уходит в opacity 0/blur 12 px, видео остаётся видимым,
основная страница после закрытия снова доступна. Проверены коллекции
на ширинах 412 и 320 px без горизонтального переполнения.

Not verified: реальный Android WebView и физический телефон, Bluetooth,
температура, расход батареи, частота кадров, TalkBack и реальный аккаунт
Яндекса. Эмулятор/Android-устройство к этому Mac не подключены.
Проверка замедленного движения общей анимации уже описана в
[IOS_MOTION_1.0.27.md](IOS_MOTION_1.0.27.md); повторная Android-проверка
в панели Animations не проводилась.

Approve — только для перечисленных автоматических, сборочных и веб-сценариев.

## Подпись и установка

VersionName: 1.0.28; versionCode: 9010021; package: `com.lomify.next`;
ARM64, минимум Android 8/API 26. Сборка выполнена с пустым каталогом
окружения, без чтения файлов `.env`.

Сертификат опубликованной 1.0.16 имеет SHA-256
`05646e3ba6891a351bd5b4afe58d66a590ad673819fb4a24e580ed81c67f6dad`.
Debug-сертификат этого Mac —
`e1f2ea2102a135d60e85cf9d80f6cbdc18ad817d3027c96f1140d9f0e5ee9be8`.
Они различаются. Поэтому тестовый APK этого Mac не обновляет опубликованную
1.0.16 поверх неё. Для такого обновления нужен прежний ключ подписи;
установленное приложение ради проверки удалять не нужно.

Неподписанный release APK сохранён для подписи прежним ключом.
Отдельный тестовый APK с подписью Mac подходит для устройства, где
приложение ещё не установлено, либо для более ранней тестовой установки
с тем же сертификатом. Android-ветка и APK пока не публикуются на GitHub.

Архивы в `src-tauri/target/android-dist/`:

- `LomifyNEXT-1.0.28-arm64-test.apk`: 27 423 264 байта;
  SHA-256 `5c4534ff71608edc52c188a969c3c195f15fbbb3f471e4c108e1678974b71051`.
- `LomifyNEXT-1.0.28-arm64-unsigned.apk`: 27 337 885 байт;
  SHA-256 `d113a941a6fe4a25df267e28a42c8cbe3fed142b59590b2877e1aa3cb0993ef9`.

Подпись тестового APK проверена `apksigner`, выравнивание нативной библиотеки
проверено на страницы 16 КиБ. Внутри APK подтверждены новый JNI-обработчик
отключения выхода, подготовка предыдущего трека и все 23 актуальных JS/CSS
файла интерфейса по байтам после распаковки Brotli. Тестовое видео и
фиктивные учётные данные не входят в архив.
